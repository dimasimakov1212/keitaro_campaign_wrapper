# Keitaro Campaign Wrapper

Веб-приложение для создания и продвинутого управления кампаниями в трекере Keitaro. 

Основной фокус сделан на удобном управлении ротацией офферов внутри потоков (streams), включая визуальное редактирование, фиксацию весов и двухстороннюю синхронизацию с API Keitaro.

## Архитектура и особенности

Приложение реализует гибридный подход к управлению данными:

1. **Создание кампаний:** Прямое взаимодействие с Keitaro API.
2. **Управление офферами:** Используется локальная база данных (PostgreSQL) для хранения *состояния* офферов в потоках. 

**Почему используется БД?**
Это позволяет реализовать продвинутый UX без потери данных:

- **Soft Delete:** Удаленные офферы не исчезают из интерфейса, а помечаются как архивные (бледные), что позволяет легко их восстановить.
- **Weight Pinning:** Возможность "закрепить" вес конкретного оффера, чтобы он не пересчитывался при добавлении или удалении других офферов.
- **Batch Sync:** Все изменения накапливаются локально и отправляются в Keitaro одним запросом по кнопке "Сохранить", что снижает нагрузку на API трекера.
- **Conflict Resolution:** При нажатии "Обновить из Keitaro" приложение автоматически обнаруживает офферы, удаленные в админке трекера, и корректно отображает их статус.

## Технологический стек

- **Backend:** Python 3.11+, FastAPI, SQLAlchemy (Async), Alembic, Pydantic.
- **Frontend:** Vue 3 (Composition API), Vite, Element Plus, Axios.
- **Database:** PostgreSQL 15.
- **Infrastructure:** Docker, Docker Compose.

## Зависимости

Зависимости устанавливаются автоматически при запуске, но при необходимости можно сделать это вручную:

**Backend (внутри Docker-образа):**
Зависимости Python устанавливаются автоматически при сборке образа через `docker compose up --build` на основе `backend/requirements.txt`. Ручная установка не требуется.

**Frontend (локально):**
При первом запуске скрипт `start.sh` автоматически выполнит `npm install` в папке `frontend/`. Вручную это можно сделать так:

  ```bash
  cd frontend
  npm install
  ```

## Быстрый старт (через Docker)

Это рекомендуемый способ запуска, так как он гарантирует идентичность окружения.

**Клонируйте репозиторий:**

  ```bash
  git clone <url_вашего_репозитория>
  cd keitaro_campaign_wrapper
  ```

**Настройте переменные окружения:**

  ```bash
    cp .env.example .env
  ```

**Сделайте скрипты запуска исполняемыми:**

  ```bash
    chmod +x start.sh stop.sh
  ```

**Сделайте скрипты запуска исполняемыми:**
Используйте предоставленный скрипт, который поднимет бэкенд с базой данных в фоне, а затем запустит фронтенд-сервер

  ```bash
    ./start.sh
  ```

Примечание: Миграции базы данных (Alembic) выполняются автоматически при первом запуске контейнера app

**Остановка приложения:**
В отдельном терминале выполните

  ```bash
    ./start.sh
  ```

**Остановка приложения:**
Frontend: <http://localhost:5173> (или порт, который выведет Vite в консоли)
Backend API Docs (Swagger): <http://localhost:8000/docs>
Health Check: <http://localhost:8000/api/health> (должен вернуть {"status":"ok"})

## Работа с базой данных и миграциями

Миграции применяются автоматически при старте Docker-контейнера, но при необходимости вы можете управлять ими вручную изнутри контейнера:
**Остановка приложения:**
В отдельном терминале выполните

  ```bash
    # Создать новую миграцию после изменения моделей SQLAlchemy
    docker compose exec app alembic revision --autogenerate -m "описание изменений"

    # Применить миграции
    docker compose exec app alembic upgrade head

    # Откатить последнюю миграцию
    docker compose exec app alembic downgrade -1
  ```
